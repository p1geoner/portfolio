# 0004. Границы слоёв на штатном ESLint вместо плагина boundaries

Дата: 2026-07-30
Статус: принято

## Контекст

Изначально правило зависимостей FSD планировалось проверять
`eslint-plugin-boundaries`. На практике плагин версии 7 использует резолвер
`eslint-plugin-import`, а конфигурация `eslint-config-next` подключает
`eslint-import-resolver-typescript` новой версии с другим интерфейсом.
Результат — ошибка резолвера на каждом файле и неработающая проверка.

Дополнительно выяснилось, что ESLint 10 несовместим с
`eslint-plugin-react`, который тянет за собой `eslint-config-next`.

## Решение

1. Зафиксирована линия ESLint 9: именно её поддерживает `eslint-config-next`.
2. Плагин `boundaries` убран. Направление зависимостей описано штатным
   правилом `no-restricted-imports`: для каждого слоя перечислены запрещённые
   шаблоны импорта (слои выше и соседние слайсы того же слоя), а также запрет
   импорта мимо публичного API слайса.
3. Структуру слоёв и сегментов проверяет `steiger` — линтер, написанный
   авторами методологии.

## Последствия

- На одну зависимость меньше, и проверка не ломается от несовместимости
  резолверов между конфигурациями.
- Сообщения об ошибках сформулированы по-человечески и объясняют, что делать.
- Правила описаны декларативно и генерируются из списка слоёв, поэтому
  добавление слоя не требует ручного перебора комбинаций.
- Цена: правило работает по строковым шаблонам путей, поэтому относительные
  импорты между слайсами оно не поймает. Этот случай закрывает `steiger`.
