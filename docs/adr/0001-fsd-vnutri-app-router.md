# 0001. Feature-Sliced Design внутри App Router

Дата: 2026-07-30
Статус: принято

## Контекст

Нужна архитектура, которая выдержит рост числа кейсов и разделов и при этом
не будет спорить с соглашениями Next.js. Feature-Sliced Design задаёт слои и
правило зависимостей, но у него есть слой `app`, а Next.js резервирует под
роутинг и `app/`, и `src/app/`.

## Решение

Роутинг Next живёт в `app/` в корне и содержит только метаданные и вызов
страницы. Все слои FSD лежат в `src/fsd/`, включая слой `app` (каркас
документа, шрифты, глобальные стили). Алиас `@/*` указывает на `src/fsd/*`.

Внутри `shared` — только сегменты по назначению (`ui`, `lib`, `seo`, `search`,
`graph`, `bitset`, `datetime`, `i18n`, `config`, `content`, `theme`), без
вложенных `lib/model/ui` внутри сегментов: этого требует спецификация FSD.

Правила проверяются автоматически:

- границы слоёв — штатным `no-restricted-imports` в ESLint;
- структура слоёв и сегментов — линтером `steiger`.

## Последствия

- Файл роута остаётся тонким, вся логика страницы тестируема отдельно.
- Нарушение направления зависимостей не проходит CI, а не обсуждается на ревью.
- Цена: два места, где описана страница (роут и слайс `pages`). Это осознанный
  обмен на возможность переносить страницы между роутами без правки логики.
