# 0005. Основной язык без префикса в URL

Дата: 2026-07-30
Статус: принято

## Контекст

Сайт двуязычный: русский — основной, английский — для зарубежных вакансий.
Нужно выбрать схему адресов. Варианты: префикс у всех языков (`/ru/projects`,
`/en/projects`) или префикс только у неосновных (`/projects`, `/en/projects`).

## Решение

Используется стратегия `as-needed` из next-intl: русские страницы живут на
чистых адресах, английские получают префикс `/en`.

Причины:

- главная аудитория получает короткие читаемые адреса без служебного сегмента;
- корень сайта отдаёт содержимое сразу, без редиректа на `/ru`, то есть без
  лишнего сетевого перехода на самом важном адресе;
- языковые версии всё равно однозначно различимы для поисковика: у каждой
  страницы есть `canonical` и полный набор `hreflang` вместе с `x-default`.

Все адреса строятся одной функцией `buildLocalePath`, которой пользуются и
метаданные, и карта сайта, и навигация — расхождение между ними невозможно.

## Последствия

- Смена основного языка — это правка `defaultLocale` в конфиге сайта.
- Неизвестные пути внутри локали перехватывает catch-all роут и отдаёт
  локализованную 404-страницу.
- Цена: без префикса у основного языка адреса двух версий несимметричны,
  поэтому ссылки на языковые версии нужно строить только через хелперы,
  а не склейкой строк. Это закреплено тем, что хелперы — единственный
  экспортируемый способ получить путь.
