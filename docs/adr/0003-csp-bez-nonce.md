# 0003. Content-Security-Policy без nonce в пользу статической генерации

Дата: 2026-07-30
Статус: принято

## Контекст

Строгая CSP обычно строится на nonce: сервер выдаёт случайное значение на
каждый ответ и разрешает только помеченные им инлайновые скрипты. Next.js
инжектирует собственные инлайновые скрипты (загрузчик и поток RSC), поэтому
без nonce или хешей им нужен `'unsafe-inline'`.

Проблема в том, что nonce уникален для каждого ответа. Значит HTML нельзя
закешировать и нельзя отдать заранее собранным — все страницы становятся
динамическими. Для сайта, где основные цели — скорость и индексация,
это заметная потеря.

## Решение

Оставляем статическую генерацию всех страниц и выдаём CSP статическим
заголовком без nonce:

- `script-src 'self' 'unsafe-inline'` — только собственные и инлайновые
  скрипты, сторонние источники запрещены полностью;
- `default-src 'self'`, `object-src 'none'`, `base-uri 'none'`,
  `form-action 'none'`, `frame-src 'none'`, `frame-ancestors 'none'`;
- `img-src` и `font-src` ограничены собственным origin.

Риск оцениваем как низкий: на сайте нет пользовательского ввода, нет форм,
нет сторонних скриптов и нет отображения внешних данных — то есть нет
источника, из которого могла бы появиться инъекция скрипта.

## Последствия

- Все страницы отдаются как статические файлы, TTFB не зависит от рендера.
- CSP закрывает всё, кроме инлайновых скриптов самого приложения.
- Если появится любой пользовательский ввод или сторонний виджет, решение
  нужно пересмотреть: тогда nonce станет обязательным, а часть маршрутов
  придётся сделать динамическими.
