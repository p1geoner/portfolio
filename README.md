# Портфолио Дмитрия Николаева

Двуязычный сайт-портфолио на Next.js 16 (App Router, RSC) с архитектурой
Feature-Sliced Design, контентом в типизированных конфигах и полным SEO-слоем.
Все страницы генерируются статически, весь текст и медиа описаны данными.

## Быстрый старт

```bash
npm ci
npm run dev            # http://localhost:3000
```

Сборка и продакшн-режим:

```bash
npm run build
npm run start
```

| Команда                    | Назначение                                                |

## Как менять содержимое

Контент не живёт в компонентах. Тексты, ссылки, метрики и медиа описаны в
`content/` — по одному файлу на смысловой раздел. Инструкция и примеры
(в том числе как добавлять картинки, гифки и видео) лежат в
[content/README.md](content/README.md).

Коротко:

- проекты — `content/config/projects/<slug>.ts`;
- о себе, портрет и контакты — `content/config/profile.config.ts`;
- опыт и образование — `content/config/experience.config.ts`;
- стек и связи технологий — `content/config/skills.config.ts`;
- домен, языки, коды поисковиков — `content/config/site.config.ts`;
- подписи интерфейса — `content/messages/{ru,en}.json`.

Каждый конфиг проверяется схемой Zod во время сборки: неверно заполненное
поле роняет сборку с указанием пути до ошибки, а не превращается в пустой блок
в продакшене.

## Архитектура

```
app/                     тонкий слой роутинга Next: re-export страниц и SEO-файлы
  [locale]/              страницы, OG-картинки, 404
  sitemap.ts robots.ts manifest.ts
src/fsd/                 Feature-Sliced Design
  app/                   каркас документа, шрифты, глобальные стили
  pages/                 композиция страниц: home, projects, project-detail, ...
  widgets/               самостоятельные блоки: шапка, подвал, таймлайн, граф стека
  features/              пользовательские сценарии: поиск и фильтры, тема, язык
  entities/              доменные сущности: project, skill, experience, company, profile
  shared/                фундамент: ui, seo, search, graph, bitset, datetime, i18n, config
content/                 весь контент и словари интерфейса
docs/adr/                записи о принятых архитектурных решениях
```

Правило зависимостей: слой видит только слои ниже себя, соседние слайсы одного
слоя друг друга не видят, импорт идёт через публичный API слайса (`index.ts`).
Это проверяется автоматически — `npm run lint` (границы слоёв) и
`npm run lint:fsd` (структура), поэтому нарушение не проходит в CI.

Файл роута в `app/` содержит только метаданные и вызов страницы:

```tsx
const Page = async ({ params }: PageProps) => {
  const { locale } = await params;

  setRequestLocale(locale);

  return <ProjectsPage locale={locale} />;
};
```

## SEO

- Метаданные собираются одной фабрикой `buildPageMetadata`: canonical и
  языковые альтернативы добавляются всегда, страницы не собирают `Metadata` руками.
- Микроразметка через `schema-dts`: `Person`, `ProfilePage`, `WebSite`,
  `BreadcrumbList`, `ItemList`, `CreativeWork` для кейсов.
- `sitemap.xml` строится из тех же конфигов, что и навигация с проектами,
  с языковыми альтернативами для каждой ссылки.
- OG-картинка генерируется под каждую страницу и каждый кейс (`next/og`),
  шрифты с кириллицей лежат в репозитории, поэтому генерация не зависит от сети.
- Основной язык живёт на чистых адресах (`/projects`), второй — с префиксом
  (`/en/projects`), связь описана через `hreflang` и `x-default`.

## Производительность

- 100% страниц — статическая генерация (`generateStaticParams` + `setRequestLocale`).
- По умолчанию серверные компоненты; клиентскими остаются только острова
  интерактивности: поиск и фильтры, переключатели темы и языка.
- Анимации только на `transform` и `opacity`, полностью выключаются при
  `prefers-reduced-motion`.
- Тема применяется до первой отрисовки маленьким инлайновым скриптом, поэтому
  нет ни вспышки светлой темы, ни отказа от статики.
- Бюджеты Core Web Vitals заданы в `lighthouserc.json` и проверяются в CI.

## Алгоритмы

Поиск и фильтры по кейсам сделаны на структурах данных, а не перебором:

- инвертированный индекс `термин → документы` даёт поиск термина за O(1);
- префиксное дерево (Trie) обслуживает автодополнение по последнему слову;
- ограниченное расстояние Дамерау — Левенштейна даёт подсказки при опечатке;
- битовые маски на `Uint32Array` пересекают фильтры по 32 проекта за операцию;
- LRU-кэш и дебаунс убирают повторные вычисления при наборе запроса;
- граф стека раскладывается по уровням топологической сортировкой (алгоритм Кана);
- «связанные проекты» находятся обходом в ширину по графу связей;
- суммарный опыт считается слиянием пересекающихся интервалов, а не сложением.

## Безопасность

- Строгая Content-Security-Policy, `frame-ancestors 'none'`, HSTS с preload,
  `Referrer-Policy`, `Permissions-Policy`, COOP и CORP.
- Внешних скриптов и трекеров нет; `remotePatterns` для изображений пуст,
  поэтому загрузка картинок из сторонних источников невозможна.
- Схемы контента запрещают внешние пути к медиа и требуют, чтобы кадры
  проектов под NDA были помечены как обезличенные.
- Ссылки у проектов под NDA отсутствуют на уровне типа: их нельзя добавить
  ни случайно, ни намеренно.
- В CI: `npm audit`, CodeQL, обновления зависимостей через Dependabot.

Причины отказа от nonce в CSP описаны в
[docs/adr/0003-csp-bez-nonce.md](docs/adr/0003-csp-bez-nonce.md).

## Деплой

Проект рассчитан на Vercel: `vercel.json` задаёт команду сборки с валидацией
контента. После первого деплоя нужно:

1. Привязать домен и проверить, что `content/config/site.config.ts` содержит его же.
2. Добавить коды подтверждения в `site.config.ts` (`verification.google`, `verification.yandex`).
3. Отправить `sitemap.xml` в Google Search Console и Яндекс.Вебмастер.
4. Проверить микроразметку валидатором Rich Results.
